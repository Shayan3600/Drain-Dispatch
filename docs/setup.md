# Setup and service activation

Node 22+ (24 recommended), npm, and Git are required. Docker and a separately installed PostgreSQL are unnecessary for local development. The original private repository was inaccessible; the product owner authorized a new repository. Local development is independent of any uninspected original backend.

Put credentials only in a git-ignored local `.env` or host secret manager. Expected settings: DATABASE_URL, GEMINI_API_KEY, GEMINI_MODEL, SPECTRUM_PROJECT_ID, SPECTRUM_PROJECT_SECRET, CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET, MODERATOR_TOKEN, WORKER_TOKEN, PUBLIC_APP_URL. Legacy PHOTON_PROJECT_ID and PHOTON_PROJECT_SECRET remain supported; populated SPECTRUM settings take precedence. Never paste credentials into repository files or chat. All credential-bearing `*.env` and `*.env.*` files, including downloaded Tiger files, are ignored; only `.env.example` is allowed in source control.

## Start locally

1. `npm ci` from the project root.
2. Only if `.env` does not exist, copy `.env.example` to `.env`. Keep `DATABASE_MODE=local` and `IMAGE_STORAGE=local` for an offline setup. Set MODERATOR_TOKEN and WORKER_TOKEN to separate random secrets of at least 32 characters. The development environment prepared in this workspace already has those secrets. Keep existing credentials; a populated database connection activates the cloud adapter.
3. `npm run dev` starts API http://localhost:3001 and website http://localhost:5173. A persistent embedded PostgreSQL database is created in `.data/postgres`; photos are saved in `server/uploads`. This is actual local PostgreSQL, **not** a Tiger Data cloud connection.
4. Optional `npm run db:seed` inserts three explicitly labeled demo incidents. In the map, enable “Include labeled demo reports.” Demo records never inflate real metrics.
5. `npm run typecheck`, `npm test`, and `npm run build` verify the implementation. `npm run test:browser` starts its own isolated API/database and client on ports 3002/5174; it never uses the cloud database.

Do not run two processes against the same embedded database directory. The worker talks to the central API rather than opening it. Tests use isolated temporary databases.

## Connect real services

Tiger Data: Use the existing PostgreSQL connection string in DATABASE_URL. Alternatively, the backend accepts PGHOST, PGPORT, PGUSER, PGPASSWORD, PGDATABASE or the corresponding TIGER_DATA_ / TIGERDATA_ fields. The Node pg adapter preserves credential values and enforces verified TLS for remote connections. Cloud mode takes priority over DATABASE_MODE. Run `npm run db:migrate`; startup also applies additive migrations under a transaction/advisory lock and configures the event hypertable when TimescaleDB is installed. Existing legacy columns and records remain intact. `/api/health` must report `databaseMode:postgresql` and `timeSeriesEnabled:true` before claiming Tiger Data verification. Existing local incidents are not migrated automatically.

Gemini: Create a key in [Google AI Studio](https://aistudio.google.com/apikey), add GEMINI_API_KEY, and choose a model available to that project via GEMINI_MODEL. Default follows current official image/structured-output docs; access must be verified. Upload a real drain photo and choose “Review photo with Gemini.” No AI results are simulated when the key is missing. Confirm the description/category yourself.

Cloudinary: Obtain Cloud Name, API Key and API Secret from the [Cloudinary console](https://console.cloudinary.com/). Set all three CLOUDINARY values and IMAGE_STORAGE=cloudinary. Upload a photo, reload the incident and verify its image URL. Local photographs are not automatically copied to Cloudinary.

Photon: Use the project at [Photon](https://app.photon.codes/) and configure one real iMessage line (shared mode or a single dedicated line). Set SPECTRUM_PROJECT_ID and SPECTRUM_PROJECT_SECRET; existing PHOTON aliases also work. Keep WORKER_TOKEN stable and identical on API/worker; rotating it invalidates messaging deduplication identities and pending draft derivations. Set API_URL to the central API and PUBLIC_APP_URL to the website. Run `npm run worker`. For shared mode, initiate a message using the project's messaging/testing link in Photon so it routes to this project. Test a real message/photo, open its confirmation link, and confirm a location; only then check the map. A phone needs a reachable public website URL; localhost links can be confirmed only on the computer running the app. Send CONSENT to allow internal status updates for incidents contributed to in a direct message; STOP cancels pending updates. Worker polls a leased outbox and rechecks consent before sending. Delivery is at least once: a crash between sending and acknowledgement can repeat an update. STOP cannot recall an already-sent or in-flight message. Multiple dedicated lines require additional routing metadata and are not supported yet.

## Deploy

When a temporary testing URL changes, set PUBLIC_APP_URL to the externally verified replacement, restart the API, and send RESUME in the same private Photon conversation. Recovery renews the private link without reuploading evidence, preserves confirmed records and refuses other senders or groups. A confirmed report opens its saved incident instead of asking for another location. Demo preview counts are separate from real community metrics; real counts can correctly remain zero while test reports are visible. Do not close a testing session before the owner finishes inspection unless its announced safety deadline expires.

Service settings are staged and reviewed in the existing project: root directory `/`, Dockerfile `Dockerfile`, one replica and no sleep. The existing `@draindispatch/server` service runs `node server/dist/index.js`, exposes only port 3001 through HTTPS, and uses `/api/health`. The existing `@draindispatch/client` service is repurposed as the persistent Photon worker, retaining the service rather than deleting it. It runs `node server/dist/photon/worker.js` with no public domain or HTTP health check. Use compiled JavaScript, not `npm run worker`, because the production image omits tsx. A future declarative project configuration should use [Railway Infrastructure as Code](https://docs.railway.com/infrastructure-as-code).

Production startup validates API and worker settings independently before database/provider calls. API requires cloud database configuration, Cloudinary, Gemini, a public HTTPS PUBLIC_APP_URL, explicit HTTPS CLIENT_ORIGIN origins, and distinct WORKER_TOKEN/MODERATOR_TOKEN values of at least 32 characters. PUBLIC_API_URL is optional for Cloudinary but must be a public HTTPS origin when present. Worker requires only Spectrum credentials, matching WORKER_TOKEN and a public HTTPS API_URL; it does not need database, image, Gemini or moderator credentials. Missing/invalid configuration errors contain setting names, never values. Keep the shared WORKER_TOKEN stable to preserve sender identities and recovery.

Separate Vercel client: included vercel.json builds client/dist and supports confirmation-link paths. Set VITE_API_URL to the public HTTPS API URL at **build time**. Add the exact Vercel origin to API CLIENT_ORIGIN; comma-separated origins are supported. Secrets must never have the VITE_ prefix. Railway proxy deployments may need TRUST_PROXY=1; set it only behind a trusted single proxy.
